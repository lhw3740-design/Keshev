# 케셰브 재현 기록과 최종 인수인계 (22단계, 학생 작성)

이 문서는 제출할 커밋을 원래 작업 폴더와 **다른 새 폴더**에 받아 21단계 설명서([STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md)) 순서대로 실행한 기록입니다. 아래 결과는 모두 이 문서에 적힌 커밋 하나를 기준으로 합니다. 서로 다른 커밋의 결과를 합쳐 전체 성공으로 쓰지 않았습니다.

## 0. 근거 종류 표기

| 표기 | 뜻 |
|---|---|
| **실제 실행** | 학생이 자기 PC에서 명령을 실행하고 화면을 직접 본 결과 (학생 보고) |
| **학생 진술** | 학생이 기억·말로 전한 내용으로, 별도 기록(캡처·로그 파일)은 남기지 않음 |
| **원문 확인** | 이 저장소의 코드·설정 파일을 읽고 맞춘 것 (실행 아님) |
| **모의 점검** | 학생 함수에 모의 입력을 넣어 출력만 확인한 것 (실제 연결 아님) |
| **포털 판정** | ALEPH 서버의 AI가 제출 커밋 원문을 읽고 내린 판정 (코드를 실행하지 않음) |
| **미확인** | 실행·확인하지 않음 |

포털 판정 통과나 이 문서의 원문 확인은 실행 성공의 증명이 아닙니다.

| 실행 시각 | 2026-10-27 오전, 11:44(KST) 이전. 정확한 분 단위 시각은 기록하지 않음 | 학생 진술 |

## 3. 재현 절차와 관찰 결과

```powershell
cd $HOME
git clone https://github.com/lhw3740-design/Keshev.git keshev-repro
cd keshev-repro
git checkout c4f6230589ea6b71b15c6b809a6436b5abf615d1
git rev-parse HEAD
node -v
cd on-client
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

`npm install` 은 하지 않았습니다(외부 의존성 없음, `package.json` 원문 확인).

| 순서 | 한 일 | 관찰 결과 | 근거 |
|---|---|---|---|
| 1 | 새 폴더에 clone 후 커밋 고정 | `git rev-parse HEAD` → `c4f6230589ea6b71b15c6b809a6436b5abf615d1` | 실제 실행 |
| 2 | 런타임 확인 | `node -v` → `v24.22.0` | 실제 실행 |
| 3 | 실행 도구로 시작 | 창 출력(아래 원문) | 실제 실행 |
| 4 | 브라우저 확인 | `http://127.0.0.1:5189/` 에서 「보호 현황」 화면이 보임. 위쪽 연결 상태 표시: **연결 없음** | 실제 실행 |
| 5 | 종료 | 실행 창에서 `Ctrl+C` → 브라우저 새로고침 시 화면이 열리지 않음 | 실제 실행 |
| 6 | 다시 실행 | 같은 명령으로 다시 시작 → 브라우저에서 다시 열림 → `Ctrl+C` 로 종료 | 실제 실행 |

3번 실행 창 출력(학생이 복사해 준 원문, 비밀값 없음):

```text
계정 연결 준비가 끝났습니다. 앱에서 확인 번호로 로그인·승인을 진행하세요.
참고: 지금 Node.js 는 v24.22.0 입니다. 수업 기준은 v24.19.0 입니다.
케셰브 연결 확인: http://127.0.0.1:5189
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
끄려면 이 창에서 Ctrl+C 를 누르세요.
```

해석: 서버가 응답했고 화면이 열렸다는 것까지만 확인했습니다. "연결 없음"은 SDP 엔진 설정 없이 켠 기본 상태(`disconnected`)로, 실제 업무 시스템 연결 성공이 아닙니다. 새 폴더에서 계정 연결 승인·AI 연결 점검은 하지 않았습니다.

## 4. 13~21단계 기능별 결과 (같은 커밋 기준)

포털 판정은 단계마다 그때 제출한 커밋에 대해 내려졌습니다. 아래 "최종 커밋에 포함"은 그 단계의 학생 코드가 재현 커밋에 그대로 들어 있는지 원문으로 확인한 것입니다.

| 단계 | 기능 / 학생 함수 | 포털 판정 | 최종 커밋에 포함 | 새 폴더 실제 실행에서 본 것 | 미확인과 원인 |
|---|---|---|---|---|---|
| 13 | 로그인·기기·세션 / `renderIdentity` | 통과(4차 13~16 모두 통과 표시) | 원문 확인 | 화면 열림, 연결 없음 상태 | 실제 사용자·기기 값: SDP 연결 없음 |
| 14 | 업무 앱 접근 판정 / `renderDecision` | 통과 | 원문 확인 | — | 실제 판정: SDP 연결 없음 |
| 15 | 접속 기록·XDR 사건 / `renderEvents` | 통과 | 원문 확인 | — | 실제 기록: SDP 연결 없음 |
| 16 | 알림·기기·세션·도움정보 / `renderStatus` | 통과 | 원문 확인 | — | 도움정보 복사는 새 폴더에서 미실행 |
| 17 | 앱 내부 AI 연결 / `renderAiConnection` | 통과(5차 17~20 모두 통과 표시) | 원문 확인, 모의 점검 | — | 실제 verified 점검: 새 폴더에서 계정·AI 승인 안 함, 운영자 권한 준비에 따름 |
| 18 | 근거가 있는 AI 사건 설명 / `renderExplanation` | 통과 | 원문 확인, 모의 점검 | — | 실제 사건 설명 호출: AI 연결·SDP 사건 없음 |
| 19 | 조치 제안·처리 결과 / `renderAction` | 통과 | 원문 확인, 모의 점검 | — | 실제 집행·효과 관측: 지원 조치 없음(supportedActions 빈 배열), 집행기 미연결 |
| 20 | 라이브러리 취약점 대조 / `renderVulnerabilities` | 통과 | 원문 확인, 모의 점검 | — | 실제 OSV 조회: 허용 목록이 비어 있으면 조회하지 않음(`.env.example` 의 `ON_APPROVED_PUBLIC_PACKAGES=[]`) |
| 21 | 실행 설명서·구성도 / `README.md`, `STUDENT_RUNBOOK.md` | 통과(포털 표시, 처음 통과 접수 2026-10-27 11:29) | 원문 확인 | 설명서 3~4장 절차가 새 폴더에서 그대로 동작 | — |

모의 점검은 최소 DOM 대역으로 학생 함수의 출력만 본 것이며, 실제 화면·실제 연결 성공이 아닙니다.

## 5. 지원 범위와 남은 사항

| 항목 | 상태 |
|---|---|
| 새 폴더에서 clone → 실행 → 화면 → 종료 → 재실행 | **실제 실행으로 확인** (같은 PC, Node v24.22.0) |
| 다른 PC·새 Windows 계정에서 실행 | 미확인 |
| 수업 기준 Node v24.19.0 에서 실행 | 미확인 |
| 실제 SDP 연결(사용자·기기·업무 앱 판정·보안 기록) | 미완료 — 운영자 설정(`-SdpHostConfig`) 필요 |
| 앱 안 AI 연결(verified)과 실제 사건 설명 | 미확인 — 새 폴더에서 승인하지 않음, 운영자 권한 준비에 따름 |
| 실제 조치 집행과 효과 관측 | 미완료 — 연동 집행기와 지원 조치 없음 |
| 실제 OSV 조회 | 미확인 — 공개 조회 허용 목록 없음 |
| 원래 작업 폴더의 `git status` | 미확인 — 학생 진술: 그 폴더에서 git 관련 설정을 확인했을 때 `false` 가 나온 적이 있어, 그 폴더가 Git 저장소인지 확실하지 않음 |
| macOS·Linux | 지원 대상 아님(실행 도구가 PowerShell 전용) |
| `public/app.js` 판본 | 13단계에 받은 판본. 0.2.14 대비 AI 요청 제한 시간(모든 요청 10초)과 일부 안내 문구가 다름 — `STUDENT_RUNBOOK.md` 8장 |

따라서 이 버전은 **검증 중인 버전**입니다. 22단계 통과는 원문 검토 기준의 수료이며, 실제 운영 인증이나 v1.0 인증이 아닙니다.

## 6. 데이터 보존·백업·복원 계획

| 데이터 | 어디에 있나 | 백업 | 복원 | 제한 |
|---|---|---|---|---|
| 학생 코드·문서 | 이 Git 저장소(`main`) | 커밋 후 GitHub 에 push | `git clone` 후 `git checkout <40자리 커밋>` (3장 절차) | push 하지 않은 변경은 백업되지 않음 |
| 계정 연결 설정·자격 보관소 | `%USERPROFILE%\.aleph-keshev-<프로젝트 경로 해시>\` (프로젝트 밖) | 백업하지 않음 (비밀 포함, 저장소·제출물에 넣지 않음) | 새 폴더에서 실행하면 실행 도구가 새로 만들고, 앱에서 확인 번호로 다시 승인 | 폴더 경로가 바뀌면 다른 설정이 됨. 다른 폴더·다른 사람의 설정을 복사하지 않음 |
| 보안 기록·기기·세션·판정 | 앱에 저장하지 않음. 연결된 SDP 호스트가 원천 | 원천 시스템 담당 | 원천 재조회 | 연결 없음 상태에서는 표시할 원천 자료가 없음 |
| 조치 기록 | 운영자가 지정한 기존 SQLite 파일에만 기록(`src/actions/README.md`), 기본 실행에서는 없음 | 운영자 담당 | 운영자 담당 | 학생 실행에서는 조치 경로가 열리지 않음 |
| 브라우저 저장소 | 사용하지 않음(`public/`, `student/` 에 localStorage·sessionStorage·IndexedDB 사용 없음, 원문 확인) | — | — | 새로고침하면 화면 상태는 다시 불러옴 |
| 비밀 설정 예시 | `on-client/.env.example` (비밀 없음) | Git | Git | 실제 값은 실행 환경변수로만, `.env` 는 `.gitignore` 로 제외 |

## 7. 다음 사람에게 인수인계

1. 3장 절차로 새 폴더에 받아 실행합니다. 정상 신호는 3장의 창 출력과 「보호 현황」 화면입니다.
2. 실제 연결이 필요하면 담당자에게 SDP 설정과 AI 앱 권한을 받습니다. 키·인증서는 저장소 밖에 둡니다.
3. 학생 화면을 고칠 때는 `on-client/student/extension.mjs` 만 수정하고 `npm run check` 로 문법을 확인합니다. 제공 파일은 수정하지 않습니다.
4. 오류는 [STUDENT_RUNBOOK.md](STUDENT_RUNBOOK.md) 7장 표에서 코드로 찾습니다.
